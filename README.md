# Takealot 自动化智能助手 - 用户使用手册

欢迎使用 **Takealot 自动化控制中心**。本软件专为 Takealot 跨境电商卖家量身打造，提供 **全自动智能跟价抢 Buybox**、**防亏底价安全保护**、**多店铺统一管理**、**Excel 批量变体跟卖** 与 **实时竞价战报看板** 等核心功能。

---

## 🚀 快速开始

### 1. 启动软件

全新安装首次启动时店铺列表为空，显示【尚未添加店铺】。请添加自己的 Takealot 店铺并填写授权凭据后，再同步商品或启动巡检。程序不会自动创建 Default 店铺，也不会自动将旁边的旧配置或 GJDATA 导入为店铺/监控。

店铺记录保存在当前程序数据目录的 `takealot.db`，会员登录不会从云端下发店铺列表。已有数据库在升级后继续保留；如出现不属于自己的店铺，请先核对是否复用了旧数据目录。店铺中心允许删除最后一个店铺，删除后恢复为空，重启也不会补建默认店铺。发布包只应包含程序、模板和文档，不应包含数据库、API Key 或本地配置。
* **Windows 用户**：解压压缩包后，直接双击运行 **`Takealot.exe`** 即可。
  > 💡 *若 Windows Defender 提示“未知发布者”，请点击【更多信息】->【仍要运行】。*
* **macOS 用户**：解压压缩包后，直接双击打开 **`Takealot.app`** 即可。
  > 💡 *首次打开若提示“无法验证开发者”，请进入【系统设置】->【隐私与安全性】，在最下方点击【仍要打开】。*
* **服务器 / 纯后台模式（可选）**：如需在云服务器（Linux/Windows VPS）长期挂机，可通过命令行添加参数运行：
  ```bash
  ./Takealot.exe --server-only
  ```
  服务只监听本机，默认自动选择空闲端口。实际地址见启动日志或 `data/runtime.json`。
  需要固定端口时指定 `--port 8000`。远程使用请通过 SSH 本地端口转发。

### 文件夹独立、多开和换电脑

每份软件使用自身旁边的 `data/`，不根据启动时的当前工作目录选择数据库，也不会在目录不可写时悄悄回退到系统目录。
Windows 把 `Takealot.exe` 和 `data/` 放在同一文件夹；macOS 把 `Takealot.app` 和 `data/` 放在同一文件夹，数据位于 App 外部，自动更新 App 时会保留。

```text
软件文件夹/
  Takealot.exe 或 Takealot.app
  data/
    takealot.db           店铺、商品、各规格底价、任务记录
    accounts/            会员 Token（不保存密码）
    preferences.json     主题、上次选择的店铺
    browser-sessions/    各店铺的浏览器资料和开关
    webview/             Windows 主窗口浏览器资料
    logs/                程序日志
    updates/             更新下载、解压和重启文件
    runtime.json         当前进程与本地服务地址
```

1. 先关闭软件，再复制**整个软件文件夹（包含 data）**到另一位置或另一台电脑，避免复制到写入中的 SQLite / 浏览器资料。
2. 分别打开不同文件夹中的程序即可多开，端口自动分配；同一 `data` 目录只允许一个进程运行。复制快捷方式或符号链接不会产生独立工作区。
3. 复制后的店铺、底价和登录状态一起保留；随后每份软件独立读写自己的文件。没有复制 `data` 的新目录保持空店铺。
4. 按当前设计，复制的 Token 仍指向同一 GoCMS 服务端会话；任一副本退出、改密或轮换该会话可能使另一副本失效。需要独立会员会话时在副本中重新登录，仍受 GoCMS 会话上限限制。

首次升级会从程序旁的旧 `takealot.db` 创建包含 WAL 已提交事务的快照，并复制旧默认配置和匹配该数据库的浏览器资料目录；原文件保留。只在这次旧库迁移中尝试读取一次旧系统凭据库，迁入失败可重新登录，之后不会写系统凭据库。
旧 macOS WebKit 验证资料与新目录格式不同，升级后需要重新验证；换电脑、系统或网络出口后，平台浏览器验证也可能需要重新完成。

macOS 主窗口使用内存浏览器，界面设置由后端保存。文件夹内的店铺持久浏览器需要 macOS 15.2+ 的 WebKit；能力不可用时显示不可用，不回退到系统资料目录。Windows 仍需安装 WebView2 Runtime，浏览器运行时和操作系统自身的诊断文件不属于应用业务数据。

可用 `--data-dir /绝对路径/工作区` 显式指定数据目录。开发运行使用 `make dev` / `make dev-server`；直接 `go run .` 时请显式传入 `--data-dir ./data`。
发布包只打包程序、文档和模板，禁止附带自己的 `data/`；该目录包含会员及店铺凭据。

### 源码构建产物

在源码目录运行 `make build`，最终程序统一放在 `dist/`：macOS 为 `dist/Takealot.app` 和 `dist/takealot`，Windows 为 `dist/Takealot.exe`。`start.sh` 使用或编译 `dist/takealot`，发布 ZIP 也输出到 `dist/`。Wails 的 `build/bin/` 仅作为中间构建目录，项目根目录不存放打包程序。

直接运行 `dist/` 内的新版程序时，默认使用 `dist/data/`；开发运行可用 `--data-dir` 指定已有数据目录。`make clean` 只清理构建产物，保留 `dist/data/`。

## 会员注册与登录

1. 启动后进入“会员账号”，注册用户名、密码及可选邮箱，再登录。
2. 在 GoCMS 后台“会员管理”创建标识为 `takealot-vip` 的会员组，给用户分配会员资格和有效期。
3. 客户端点击“刷新会员状态”，验证通过后即可使用业务功能。

开发环境默认 GoCMS 地址为 `http://127.0.0.1:18080`。正式部署必须指定 HTTPS：

```bash
./Takealot --gocms-url https://cms.example.com --member-group takealot-vip
```

也可设置 `TAKEALOT_GOCMS_URL` 和 `TAKEALOT_MEMBER_GROUP`；启动参数优先。
这些配置在本地进程启动时读取，不通过前端 API 修改。

- 会员服务需使用 GoCMS v0.1.59 或更新版本。客户端通过 `POST /api/v1/auth/token` 登录，
  后续会员请求统一使用 `Authorization: Bearer <access_token>`，不使用 Cookie。
- Token 仅保存在本地 Go 进程及当前 `data/accounts/`，不返回给前端；密码不落盘。
  凭据文件不绑定机器或绝对路径，复制整个目录可以携带仍有效的登录状态。
- 凭据文件无法写入时仅保留内存会话，界面会提示；重新启动可能需要重新登录。
- 携带同一账号的有效 Token 再次登录会轮换会话，不额外占用 GoCMS 登录名额。
- 登录会话达到上限时，退出其他客户端或让管理员在 GoCMS 撤销旧会话。
- 每30秒在线复查会员状态；缓存超过45秒或会员到期即拒绝业务操作。
  启动调价/跟卖任务前会主动在线校验。
- 断网、服务不可用、账号禁用、会话撤销、VIP到期都会阻止后续受限操作；
  进行中的调价会停止，跟卖会在后续提交点停止。已发出的第三方请求无法撤回。
- 主动退出会停止调价并撤销 GoCMS 会话。退出时服务不可用则在本机锁定，
  不再自动恢复；可恢复网络后重试退出或重新登录。
- 客户端已移除旧离线激活码和机器码验证逻辑。旧 `.license` 文件和数据库中的旧授权字段不会再读取；
  不自动将旧授权转换成 VIP，请管理员按用户实际授权手动迁移。
- 这是单机工作区的会员准入控制。切换账号不会隔离或清除已保存的店铺数据。

### 抓价异常自动反馈

- 登录后的自动调价任务遇到 Cloudflare 拦截或前台价格抓取失败，会异步调用当前会员服务地址的 `POST /api/feedback`，无需用户点击提交。
- 管理员在 GoCMS 后台“信息反馈”的默认反馈分类查看记录；标题区分“Cloudflare拦截”和“抓取失败”，正文包含店铺、TSIN、PLID、发生时间和错误详情。
- 提交使用 URL 编码表单，携带当前会员 Bearer Token 及会员标识，不需要后台 API Key；旧 `.api.key`、`XIAN_*` 上报配置及内容分类 ID 不再使用。反馈按会员服务域名归属站点。
- 会员资料没有电话，默认表单的电话字段明确填写“未提供（客户端自动反馈）”。此接口为公开留言接口，会员标识仅作为反馈来源信息。
- 同一店铺、商品和异常类型每 15 分钟最多提交一次，提交失败也限流；后续再次发生异常时重试。请求超时为 10 秒，失败原因写入“实时日志”，不阻塞巡检。
- 若管理员给默认反馈分类增加验证码或其他必填字段，自动提交可能被拒绝，具体原因会出现在日志中；自动上报依赖该表单允许上述字段直接提交。

## 📖 核心使用步骤

### 第一步：配置店铺与卖家授权
1. 打开浏览器登录 [Takealot 卖家后台 (Seller Portal)](https://sellers.takealot.com/)。
2. 在键盘上按 `F12` 打开浏览器开发者工具（或鼠标右键选择“检查”），切换到 **网络 (Network)** 标签页。
3. 在卖家后台任意点击一个页面（例如“Offers”），在网络请求列表中找到任意一条以 `seller-api.takealot.com` 开头的请求。
4. 查看该请求的 **请求标头 (Request Headers)**，找到并复制 **`authorization`** 字段的值（格式通常为 `Key 1234567890abcdef...`）。
5. 回到本软件界面，点击左侧菜单的 **【店铺管理】** 或 **【配置设置】**：
   - 将复制的 Token 粘贴到 **Authorization** 输入框。
   - 点击【测试连接状态】，显示“连接成功”即代表店铺已成功绑定。
   - *（支持绑定多个店铺，点击左侧店铺切换栏可快速新增并切换管理）*。

---

### 第二步：配置自动调价参数
在【参数配置】页面中，设置调价的基本规则：
* **轮询间隔（分钟）**：调价循环的周期，建议设置为 `3 ~ 5` 分钟。
* **降价步长 (R)**：当发现竞品价格低于我方时，我方每次下调的金额（例如设为 `1`，即比对手便宜 1 兰特）。
* **提价步长 (R)**：当竞品提价、竞品缺货或我方独家在售时，系统每次回调价格的金额（赚取更多利润）。
  > 系统会读取前台真实报价列表，按"第二名竞品"的价格跟随涨价，始终比对方低一个提价步长；
  > 已获取可靠竞品价时，提价不会超过该商品设置的 **【最高限价 (Max Price)】**；未设置时直接按竞品价减步长计算。独家在售时，必须设置封顶价才会逐步提价。
  > 多规格商品按 TSIN 核对规格，按卖家 ID 排除自己的报价，避免把前台尚未更新的自身旧价当成竞品追降。遇到 403/验证页面、竞品卖家身份无法确认或规格解析失败时，本轮暂停竞品跟价，并在【实时日志】显示原因；跟涨还需确认展示报价完整。已确认本店具体商品售价低于底价时，可单独执行底价恢复；访问会话要求验证或任务已取消时停止提交。
* **最低底价保护**：自动跟价以已保存底价为下限；同步商品或平台售价变动不会重算、覆盖底价。若已确认本店商品的当前售价低于底价，巡检会优先回调至底价，不受竞品价和提价步长限制；底价高于封顶价时暂停该商品调价并提示修正。访问验证未完成、会员失效或报价提交失败时，仍需处理相应异常后才能恢复售价。
* **价格独立配置**：软件只修改实际售价，不按比例生成或修改平台参考划线价（RRP）。底价与封顶价由商家直接填写，不随售价或 RRP 自动折算；平台拒绝报价时显示失败，保留原有限价。

设置完成后点击底部的 **【保存配置】**。

### 网页访问验证与持久会话

桌面版顶部“引擎态势”前的 **【访问会话】** 可以在主窗口内完成网页验证。待验证时入口显示橙色和店铺数量。Windows 使用 Microsoft Edge WebView2 Runtime；macOS 的文件夹内持久会话需要 15.2 或以上版本。纯服务器模式和普通浏览器控制台不提供验证面板。

1. 停止该店铺的巡检和跟卖任务，进入【访问会话】，选择店铺并点击【启用持久会话】。请求方式按店铺保存。
2. 左右两侧同时显示【卖家接口】和【商品接口】，每侧可独立重载。若出现 Cloudflare 页面，由用户手动完成验证。卖家页面初次没有携带 Key，可能显示权限提示；点击【检查并恢复】会使用已保存的店铺授权检查连接，避免把 Key 暴露在页面地址或日志中。
3. 两个接口检查通过后，面板持续显示绿色提示“验证通过，可以关闭此面板”，点击【完成并关闭】即可。商品同步、抓价及价格提交都会通过该店铺的原生浏览器会话执行，现有底价保护、商品身份校验与会员校验继续生效。关闭面板会保留页面和会话；尚未启动的巡检仍需手动启动。
4. 再次遇到验证时，相关店铺会显示【等待验证】，取消当前轮价格计算并提示打开会话面板。验证通过后，已经运行的巡检从新一轮比价开始；手动停止的任务不会自动启动，手动暂停状态也不会被覆盖。跟卖写入不会在验证后自动重放，需检查平台实际结果再重新操作。
5. 如需恢复直接请求，先停止任务，再点击【切换为直接请求】。直接请求遇到带验证标记的响应时，桌面版会提示检查访问会话。

会话资料保存在当前软件的 `data/browser-sessions/`，按店铺和代理隔离；复制软件文件夹时可一并带走。重启后仍需点击【检查并恢复】确认是否有效。不会把 Cookie 导出给 Go 请求，也不会把主程序的本地接口绑定提供给 Takealot 网页。验证不是永久有效，换电脑、出口变化或站点策略变化可能要求重新验证。

Windows 支持无账号密码的 HTTP、HTTPS、SOCKS5 店铺代理；代理变化后需重新检查会话。带认证的代理请改用系统代理或 TUN。macOS 会话当前使用系统网络路径，需要清空店铺代理设置。切换到纯服务器模式时，已经启用持久会话的店铺不会悄悄改回直接请求。

价格提交若发生响应丢失或服务错误，不会自动重放写入。请回读平台当前价格后再操作；界面出现“提交成功”与市场前台最终显示新价格仍是不同阶段。本次集成的验证范围见 [集成验证记录](docs/browser-session-integration.md)。

**同链接防竞争自动生效，无需设置**：同一系统内，最先处理商品的店铺会成为该商品的改价负责店铺，其他店铺遇到相同 TSIN 或 PLID 时自动跳过，并在日志中显示原因。归属会保存在本地数据库中，暂停、取消监控或重启不会转移归属；删除负责店铺后，其他店铺才可重新认领。不同商品仍可由不同店铺正常改价。此规则适用于自动调价，从更新后首次处理商品时开始认领。

### 第三步：商品监控与底价设置
1. 点击左侧菜单 **【自动竞价】**。
2. 点击右上角 **【同步在售商品】**，系统将自动从店铺拉取当前所有已上架的商品。
3. 列表中会实时展示：
   - **实际售价** / **库存数量**
   - **竞品最低价** / **跟卖卖家数**
   - **当前状态**（处于优先 / 失去优先 / 独占在售）
4. 为需要开启调价的商品勾选监控。单规格商品可直接填写 **防亏底价** 和 **封顶价**；同一店铺、同一 PLID 下有多个在售规格时，点击列表中的 **【配置规格价格】**，在弹窗中按各规格的标题、SKU、TSIN 和当前售价分别填写底价与封顶价。搜索和筛选不会隐藏弹窗中的其他在售规格，不同店铺分别配置。
   > ⚠️ **安全防线**：最低底价是您的成本红线，输入或批量设置后须点击【保存已修改的配置】才会生效。竞品低于底价时仅降至底价，当前价已低于底价时优先恢复。手动改价保留已保存的底价和封顶价，不计算新底价；底价与封顶价统一在自动竞价列表中配置。批量设置底价直接填写金额，不按售价或 RRP 折算。
5. 弹窗内点击 **【保存规格配置】** 即可保存本次修改的规格保护范围，不改变当前售价或监控勾选状态。单规格输入框及监控勾选的修改仍使用右上角 **【保存已修改的配置】** 保存。

勾选监控必须设置大于 0 的整数底价，封顶价不能低于底价。旧数据缺少底价或范围冲突时，引擎跳过该商品并记录日志；同步不会自动填充或覆盖商家底价。保存规范的 TSIN/PLID 配置会替换旧 TSIN-only 监控，避免同一规格重复调价。

### 第四步：一键开启全自动跟价
1. 返回左侧 **【控制看板】**。
2. 点击顶部的 **【启动跟价】** 按钮。
3. 系统将立即开始多协程自动化轮询：
   - 自动获取最新竞品数据。
   - 智能比价计算最佳 Buybox 价格。
   - 自动提交官方 API 更新售价。
   - 界面右上角会实时展示下次调价倒计时与实时战况日志。
4. 需要暂停时，随时点击 **【暂停】** 或 **【停止】** 即可。

排查问题时，可在【实时日志】选择级别或搜索关键词，再点击 **【导出日志】** 保存文本文件。桌面版会弹出另存为窗口，浏览器版会下载文件；内容包含完整时间、日志级别、店铺信息和筛选条件。选择 `ALL` 并清空搜索可导出当前保留的全部日志。运行日志最多保留最近 500 条，重启后清空，请在问题出现后及时导出。

巡检执行期间显示“本轮执行中”；本轮结束后才开始计算下一轮倒计时，并记录计划时间。遇到 API 限流、网络错误或服务暂不可用时，实时日志会显示等待时长和重试次数。卖家目录持续限流后，本轮停止重复搜索目录，继续核对前台报价；无法确认报价完整或独家状态的商品仍会跳过。点击停止会取消本轮请求及重试等待。

前台报价卡片未展示本店时，如果已确认是同一 TSIN、报价中的卖家 ID 均可识别且竞品确实更便宜，仍可按底价保护规则跟降；本店报价缺失时不会据此跟涨或判定独家。

### 第五步：Excel 批量跟卖（可选）
如果您需要批量跟卖爆款或录入新商品：
1. 在【批量跟卖】下载最新的 **`批量导入模板.xlsx`**。原有“库存、最低价、URL”三列表格仍可导入；最低价是底价，不是初始售价。
   - **URL**：商品链接或 PLID，必填。
   - **TSIN（可选）**：指定一个具体规格；留空则在预览时展开该链接的全部规格。一个链接可按不同 TSIN 分多行填写。
   - **最低价**：该行的默认防亏底价，展开后可逐规格修改，每个勾选规格的底价须大于 0。
   - **初始售价（可选）**：该规格上架时的售价；留空或填 0 时，按其最新市场价减 R1 计算，并限制在底价和封顶价之间。未取得市场价时使用该规格底价。
   - **封顶价（可选）**：该规格自动提价的上限；留空或填 0 表示未设置。填写时须不低于底价。
   - **库存 / 计划备货量**：仅保存备货计划，不会设置平台可售库存。平台仓商品需另行完成入仓；自有仓库存及备货天数需在卖家后台配置。官方库存写入需要明确的 `merchant_warehouse_id` 和 `leadtime_stock`，不能将导入数量当作仓库库存直接提交，参见 [Seller API 官方文档](https://seller-api.takealot.com/api-docs/)。
2. 选择一个具体店铺，将填写好的 Excel 拖入上传区域。可在导入清单调整默认价格及指定 TSIN。
3. 点击【解析规格并核对价格】，查看每个规格的颜色、尺码、TSIN 和市场参考价。链接级底价只用于填充初始值，例如单件装可设底价 R80，三件装可设 R210。
4. 在【规格价格核对】中分别修改新规格的底价、封顶价和初始售价，并勾选要上架的规格。已有商品的日常底价与封顶价统一在【自动竞价】配置；本店已跟卖或身份不完整的规格不可重复上架。重复 TSIN、链接解析错误须先修正后重新解析。
5. 点击【上架已勾选的 N 个规格】。系统会重新核对每个 TSIN 所属链接和本店跟卖状态，只上架所选规格，并将成功规格分别加入调价监控；现有规格及其他店铺的底价不会因链接展开而统一覆盖。

上架成功后，新规格立即进入本地商品列表，初始显示已提交的售价和 TSIN；平台商品同步会补齐标题、图片和实际库存。上架成功不代表已满足平台可售条件。自动改价始终重新读取平台的真实 Offer ID 和售价，不用本地上架缓存直接提交改价。

## ❓ 常见问题 (FAQ)

#### Q1：提示“授权失败 (401 / Unauthorized)”怎么办？
* **答**：Takealot 卖家后台的 Token 可能会随重新登录或过期而失效。请按《第一步》重新在卖家后台抓取最新的 `authorization`，粘贴到软件中保存并测试连接即可。

#### Q2：为什么有些商品明明被抢走了 Buybox，软件却没有降价？
* **答**：请优先检查该商品的 **最低底价 (Min Price)**：
  - 如果竞争对手的价格已经低于您设置的最低底价，系统的“防亏损保护机制”会坚决拒绝降价，避免产生亏损。
  - 请确认该商品是否已勾选【开启监控】并点击了【保存】。

#### Q3：软件运行时可以关闭电脑或断网吗？
* **答**：软件需要在开机且联网状态下才能与 Takealot 服务器通信调价。建议在日常办公电脑上保持软件最小化运行；或者部署在 24 小时运行的 Windows / Linux 云服务器上。

#### Q4：数据存储在哪里？更换电脑如何迁移？
* **答**：软件所有的店铺配置、商品底价和运行日志全部存储在同目录下的 **`takealot.db`** 数据库文件中。
  - 更换电脑时，只需将原来的 `takealot.db` 拷贝到新电脑的软件目录下，即可无缝还原所有数据与配置。

#### Q5：多店铺支持如何使用？
* **答**：在左下角点击【新增店铺】，输入店铺名称并填写对应店铺的 Authorization。调价引擎会同时为所有已激活的店铺并发进行独立比价与调价，各店铺参数互不干扰。
